# PALLADIUM store: architecture (Module 1: data layer)

## Stack
Next.js (App Router) + React + TypeScript + Tailwind, PostgreSQL 16, Prisma, jose/bcrypt for auth, zod for validation.
Money is stored as integer centavos. Timestamps are UTC in the database and shown in Asia/Manila.

## Key decision: inventory and order rules live in the database
Stock and order state changes run inside PostgreSQL functions (`prisma/migrations/0003_functions`).
The Next.js API calls them with `prisma.$queryRaw`. Reasons: they are atomic, they row-lock inventory so two
buyers cannot take the last unit, and they cannot be bypassed by a bug in one route.

| Function | What it does |
|---|---|
| `pal_ledger` | The only way stock changes. Locks the inventory row, blocks negatives (unless `allowOversell`), updates counters, appends a ledger row, raises low/out-of-stock notifications |
| `pal_adjust_inventory` | Receive, add, remove, adjust to a counted number, damaged, returned |
| `pal_transfer_inventory` | Move stock between locations (ledger out + in) |
| `pal_place_order` | Reads prices from the DB, validates the discount, reserves stock, snapshots prices onto the order, idempotent on `idempotencyKey` |
| `pal_confirm_order` | Payment received (or COD confirmed): reserved stock becomes a sale |
| `pal_cancel_order` | Releases the reservation, or restocks if already confirmed |
| `pal_refund_order` | Full or partial refund with optional return-to-stock per item |

## Stock model
`onHand` = physical units. `reserved` = held by unpaid orders. Available = onHand - reserved.
Order placed: reserve. Confirmed: onHand and reserved both drop. Cancelled: release or restock.
Every step writes an `inventory_transactions` row with previous and new values.

## Database rules enforced by PostgreSQL
Append-only ledger (update/delete blocked), orders and order items cannot be deleted, no negative stock,
ledger arithmetic check, unique SKU/barcode/order number, case-insensitive unique emails and discount codes,
email format check, order items copy name/SKU/price at purchase time.

## Future-ready hooks
`locations` (warehouse, store, consignment) with per-location stock; `Order.shippingZone`; `Payment.provider` and `rawPayload`
for GCash/Maya/card providers; `Shipment.courier` for courier APIs; `Product.isDemo`; role enum for staff and retail accounts.

## Files
- `prisma/schema.prisma`: source of truth for tables
- `prisma/migrations/0001_init`: tables (generated by `docs/gen_migration.py`, replace with `prisma migrate dev` when npm is available)
- `prisma/migrations/0002_constraints`: checks, triggers, unique indexes
- `prisma/migrations/0003_functions`: order and inventory functions
- `prisma/migrations/0010_palladium_live`: unique index on orders.txId (one blockchain transaction pays one order)
- `prisma/tests/workflows.sql`: database workflow tests (`bash docs/run_db_tests.sh`)
